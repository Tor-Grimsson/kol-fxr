Decisions taken on the build, each where it bit: § 2 Vector keeps its order (its source is an SVG picked for the Distressor itself); § 4 tilt is canvas row/column strips inside the one `fx-media` stage, not a pixi homography (canvas 2D gets `u`, stays export-safe, needs no pixi cache token); § 5 Scanline's own Pulse and Form › Sweep stay and compose with the rig (they are the Scanline generator's too); § 9 no backfill — a file gets its thumb on its next save; § 10 lives on the labs Motion / Animation tabs (the editor inspector not wired); § 15 the default model is the Stanford Bunny (Stanford 3D Scanning Repository, Turk & Levoy 1994 — free use with credit) at `meshes/stanford-bunny.obj` in the `kol-media` R2 bucket; generator post-processing is the canvas tier on the Style tab.

## 1. Primary hover is the sunken well (DS — kol-theme)
- **Seen:** the labs entry card's rows (*"hover state here should be sunken no?"*) and the rail's **Randomize all** (`LoopFields.jsx:271`, `tone="primary"`): *"hover state is same color as background??? what is that? ghost?"*
- **Why:** kol-theme 0.171.0 draws primary hover as the rest fill minus 8 (`ButtonPrimaryHoverDeeper`, `kol-components-molecules.css:2008`). Dark: rest `--kol-surface-secondary` `#19191d` → hover `#111115`, and the rail is `--kol-surface-primary` `#121215` — the hover lands on the rail's colour and the button vanishes.
- **Fix:** `--kol-tone-hover-bg` for primary → `--kol-surface-sunken`; press one step past it. One ticket to kol-ds-ui; both places take it on the bump, nothing local.

## 2. Effects asks for the media first (here)
- **Seen:** the labs entry card goes Effects → effect type → then the media card (`LabsCatalogCard.jsx:12`). *"if I select effects, shouldnt the image or media be selected before you select effect type?"*
- **Fix:** the Effects door opens the media card (image · video · webcam) first, then the effect groups. Vector the same — it needs a source too.

## 3. A scope that is the whole tab is not a scope (here)
- **Seen:** Scanline → Motion: **Randomize motion** and **Motion** under it. *"do both buttons do the same thign? … shouldnt it be 2 buttons pulse and sweep? if its a subset for randomise motion (all)"*
- **Why:** `deriveScopes` (`rolls.jsx:44`) makes one button per `section`; Scanline's motion params are one section, `Motion` = Pulse + Sweep — the same set `Randomize motion` rolls (`EffectsPanel.jsx:253`). Two buttons, one action.
- **Fix:** in `StageRolls` (and Generate's grid, same rule), a scope whose params equal the tab's whole roll set is dropped; when that leaves no scopes and the tab has more than one param, the subsets are the params themselves — one button each (Pulse · Sweep), ⌥ resets that one.

## 4. The media moves too — as a chain stage (here)
- **Seen:** an effect page's Motion tab moves only the effect. *"would you not also want to somehow control the media? f.e. repeat x and y? or sweep image movement? or slight 3d tilt? … the effect is very alive, but it could be combined with some basic media motion as well"*
- **Not** on the photo schema or the viewport fold: the fitted source canvas is cached for stills and rebuilt per tick only for video (`LayerRenderer.jsx:1150`) — animating it there puts every still on the video path and invalidates every downstream per-source cache each frame; and photos never pass through `drawLoopFrame`, so the viewport camera cannot reach them. **Not** a CSS transform on the element: export snapshots the live chain canvas (`build.js:156`) and would miss it.
- **A canvas-tier stage `media`, first in the chain** (the canvas tier always runs first, `filterChain.js:24`): one `createPattern(src, 'repeat')` with an animated matrix gives **Tile X / Y** (1–8), **Drift X / Y** (whole tiles per loop, signed), **Rotate** (whole turns) and **Zoom** (its pulse is a binding, not a param) — ~25 lines, seamless by construction. Stage params are ordinary params, so bind dots, keyframes, rolls, save/load and export come free. The chain already runs on 2d loops (`build.js:484`), so the same stage tiles and drifts a generator.
- **Tilt is a pixi-tier stage:** a homography in a fragment shader (~30 lines GLSL) with Tilt X / Y (degrees; one swing per loop through a binding) and Perspective. It batches with the other pixi filters and leaves the terminal GL slot free — not a three.js plane engine (one engine stage, always last, would exclude Lens/Distortion). ⚠ `runPixiPass` caches stills by `src|key` (`LayerRenderer.jsx:1163`): an animated tilt needs `t` in that token.

## 5. Scanline joins the sweep rig; the rig gains origin and travel (here)
- **Seen:** Scanline → Motion → Sweep, one slider. *"what sweeps, I feel like there could be sweep from and direction and size etc?"* · *"and pulse type, and frequence?"* · *"origin? as well, it seems to origin from top left or left, and only one direction"*
- **Today:** `sweep` (`filters/scanline.js:89`) is an amount on the engine's own size wave; travel and width are fixed inside the engine. The full rig exists — `filters/sweeps.js`: Shape (linear bar · radial pulse · traveling wave · radar · noise drift), Target (brightness · geometry · reveal), Amount · Speed · Width · Angle, stacking, presets, integer cycles per loop. ASCII · Halftone · Bitmap opt in with `sweeps: true`; Scanline never did. The rig dropped labs' `centerX/centerY` — the samplers pin 0.5, 0.5 (`sweeps.js:48`) — and a band runs one way (negative `speed` reverses, nothing exposes it).
- **Fix, once in the rig:** every sweep gains **Origin X / Y** (a canvas pick, not two blind sliders — where a radial/radar sweep centres, where a linear one starts) and **Travel** (forward · reverse · ping-pong, still whole cycles). Scanline declares `sweeps: true`; its engine `sweep` and `pulse` retire (drafts holding them map to a geometry sweep at that amount). "Pulse from a point" is a radial sweep targeting geometry — already a shape. Pulse **type and frequency** are NOT per-effect params: they are the LFO binding (sine · triangle · square, rate in cycles per loop, `sources.js:73`) — item 10 is how the user reaches it.

## 6. The seed only where it earns its row (here)
- **Seen:** Scanline → Motion: a Seed field over two sliders. *"what does seed do for us here?"*
- **Why it is there:** it is the ROLL seed (`rolls.jsx:163`) — the number behind the last Randomize, kept on the layer as `_rollSeed`; typed back in, the next press replays that roll. Scanline has no randomness of its own. Over Pulse + Sweep the values are readable; the seed recovers nothing.
- **Fix:** `StageRolls` (and Generate's roll block) shows `SeedField` only when the tab's roll set is more than a handful of params (start at > 4; settle on the walk). Hidden on this tab and most Motion tabs; kept on generator Generate tabs.

## 7. The label column fits its panel (here)
- **Seen:** Scanline → Motion, Pulse and Sweep sliders. *"shouldnt the sliders use more space? they are so narrow"*
- **Measured** (dev, 2026-10-09): the row is 231px, the label column `RAIL_LABEL_W` = 112 (sized for "ORIGINAL COLOR"), the slider got 42. The value box also runs wide: its width comes from the HTML `size` attribute, which pads past N characters — "0.70" sits in ~72px; sized in `ch` + padding it measured 53.
- **Fix:** the value box sized in `ch` + padding (`RangeField`, `AutoControls.jsx`), and each rail panel sizes its label column to its own longest label (measured once per panel), so every control in a panel still starts on one x; Scanline's sliders roughly double. Agreed by the user.

- **Seen:** Scanline → Motion: Seed / Randomize run straight on from the sliders. *"I also feel like we are missing a divider no"*

## 9. Home's file cards show their thumbnail (here)
- **Seen:** Home, signed in — Stripes · Scanline drift · Star morph as blank cards; then "a", saved 2026-10-09 with an image, also blank. *"I thought we had screenshots on save? these need screenshots"*
- **Why:** saves carry a 240px webp `thumb` since 2026-10-09 (`useComposeFile.js:111`) and the Files dialog shows it — Home's file card is `media: false` (`AppLayout.jsx:375`). The three older files predate thumbs. "a" may lack one in the file too: the capture rasterizes the frame as an SVG, and an unfiltered photo goes in as `<image href="blob:…">` (`build.js:208`), which an SVG drawn as an image cannot load — an editor-uploaded photo without an effect captures blank. (The live site may also still be on a build from before thumbs — the failed deploy was `fxr-1014`.)
- **Fix:** Home's card media = `<img src={file.thumb}>` when present; the capture draws photo layers through `drawImage` (or inlines the source as a data URL) before the SVG raster; files without a thumb get one on their next save — or a one-off backfill renders each saved file off-screen and stores its thumb.

## 10. Every effect and generator has a Motion tab — the modulation system is it (here)
- **Seen** (the review's count, 2026-10-09): of 68 effects, all 27 `fx-*` canvas filters and 30 of 35 pixi filters carry zero motion params (chromatic, edge, pixelsort, kaleido, mirror, posterize, threshold, blur, pixelate, noise · twist, bulge-pinch, displacement, glitch, rgb-split, the blurs, simplex-noise, godray…); Lens 1 (flow), Slitscan 1, Trails 2, Scanline 2, Dither 1, Glass 4. The ones motion would transform are exactly the empty ones.
- **Why hand-adding is wrong:** every param already binds — LFO sine · triangle · square with rate in whole cycles and phase, audio bands, MIDI, mouse, joystick, expression, keyframes — nested stage params included (`resolve.js:75`). That IS "pulse type + frequency" for any slider. The gap is presentation: the dots hide by default (M), and an effect with no `tab: 'anim'` param shows an empty Motion tab.
- **Fix:** the Motion tab of ANY effect or generator lists its bindable params, each with one-press motion — **Breathe** (LFO sine, 1 cycle, ±20% around the current value), **Sweep** (triangle), **Jitter** (square at 8) — and the full `ModulationEditor` behind each; a bound param shows its source as a chip. Per-effect `tab: 'anim'` params stay where an engine has real motion (Disco, Rutt-Etra). Rolls on this tab roll the bindings' rates and depths.

## 11. The camera reaches every generator; the media stage reaches them too (here)
- **Seen** (the count): only `shape` (16) and `pattern` get the universal camera — Spin · Zoom · Pulse · Wobble + the time shape (`contract.js:50`). `field` (10) keeps its own camera schema with no own motion; `penrose` (55) has neither, though contract.js says a wrapping camera on a sim is valid, just never schema'd; `distress`, `paratype`, `modulator`, `abstract` have nothing. `math` (7/10), `optic` (3/3) and Scanline are the developed ones.
- **Fix:** the fold list grows one line per group — field (folded beside its own camera), penrose, distress, paratype, modulator — the Penrose sims excluded from the TIME warp only (a warped clock on an accumulating sim is not a loop). Item 4's `media` stage applies to a loop layer as to a photo (tile a generator ×3 and drift it).

## 12. Home opens in grid, signed in or not (here)

## 13. Uploaded media lives in the file, not in one browser (here)
- **Seen:** *"what happens to the uploaded media when you save? … does it go to the saved file?"*
- **Today, two paths:** editor uploads (footer, drag-drop) set `src` to a `blob:` URL and park the bytes in this browser's IndexedDB (`EditorFooter.jsx:101`, `CanvasArea.jsx:359`); the saved file carries the dead URL, the D1 sync pushes it as-is, and only the DRAFT restore re-links the bytes (`state.jsx:1783`) — a saved file opens with no image after a reload and never on another device. Labs uploads read the image as a data URL into `src` (`LabsSourcePicker.jsx:61`) — the whole photo as base64 in localStorage and in the D1 row, no size cap anywhere.
- **Fix:** one upload path for both chromes — the image is decoded, downscaled to the canvas's long side (cap 2048, webp q0.85) and stored as a data URL in `src`; the clip store stays for video only. Opening a saved file hydrates clips the way the draft does (one call). `ponytail:` data URLs in localStorage hit the 5–10 MB quota with a handful of photos; the upgrade is an asset store (Worker + an R2 bucket owned by this app — a different thing from the read-only CDN library ruling), which is a user ruling, not a build.

## 14. A block-corruption effect — `fx-blocks` (here)
- **Seen:** a 1-bit dithered portrait with big black squares thrown across it, blocks of the image shoved sideways, and small clusters of pure blue / green / magenta pixels. *"a post processing fx or just a regular effect that in glitchy blocky effect, maybe has settings for distortion and irregular chromatic aberration? dunno what would be best?"*
- **Today:** nothing does blocks. pixi `filter-glitch` is horizontal slice offsets (`pixi/defs.js:165`); `fx-chromatic` is one global RGB offset breathing on a sine (`fxRadar.js:241`); `fx-pixelsort` and `fx-noise` are neither. The Post-processing rack is seven canvas ids (`effectCategories.js:43`).
- **Which:** one canvas-tier filter def over `runFx` (`fxCore.js:127`, ~80 lines of pixel work), claimed by the Post-processing group AND reachable as a page effect — in the chain a "post fx" is just a stage after another, so one def serves both. Canvas, not pixi: the look is grid work on a 1-bit image and must stay crisp; a pixi stage resamples. It stacks after Dither / Halftone / Scanline (same tier) and before any GL engine.
- **Params:** Block size · Density · Seed; **Displace** (blocks shoved by whole blocks, amount + direction bias); **Drop** (blocks filled solid — the black squares — ink or bg, coverage); **Channel noise** (clusters of pure R/G/B/C/M/Y pixels, coverage + cluster size — the coloured dots); **Chromatic** (per-block RGB offset, each block its own vector — the "irregular" aberration — amount + spread); **Tear** (row bands shifted, like the slice glitch, count + height). Motion: **Rate** = reseeds per loop, whole number — the block pattern is `hash(block, floor(u·rate))`, so it changes `rate` times a loop and returns at u=1 (seamless); **Hold** keeps a fraction of blocks across reseeds so it flickers rather than churns. Every param binds (item 10), so Density on audio level is free.

## 15. A mesh in the 3D scene — lit, spun, and filtered live (here) — BUILT 2026-10-10
- **Seen:** *"rotate some 3d forms like we already do in 3d scene, but could also accept .obj uploads such that f.e. a human form or statue could be rotated on a loop with some lighting controls, then that could be exported as video and imported to use with f.e. ascii fx?"*
- **Today:** `scene3d` (`gl/catalog.js:245`) is three.js: a primitive select (torus knot · torus · box · icosahedron …), standard / normal / wireframe material, Motion presets + keyframes, drag orbit (`camTheta/camPhi/camDist`), `drive: 'seek'` on a duration — so a whole-turn spin is already seamless on the loop clock. Lights are hardcoded in `PrimitiveEngine.js:52` (ambient · hemisphere · key · fill), no params. `OBJLoader` · `GLTFLoader` · `STLLoader` · `FBXLoader` ship inside `three` — no new dependency. The distress loop already takes an uploaded file through the source picker's `svgMode` (`LabsSourcePicker.jsx:43`) — the pattern for a mesh is identical.
- **The round trip is the wrong seam:** an engine loop returns `EngineLoopLayer` before any filter check (`LayerRenderer.jsx:145`), so a GL loop cannot carry a canvas or pixi stage today — that is the whole reason export→import looks necessary. The webcam path already feeds a live element into the chain per tick (`FilteredPhotoLayer`, `LayerRenderer.jsx:1106`); the mirror of `EngineLoopFilterLayer` reads the engine's canvas as the chain `src` the same way. Then the statue + ASCII is one layer, live, at full resolution, exportable as webm as today.
- **Build, three parts:** (a) `primitive: 'mesh'` + `meshSrc` through a `meshMode` of the source picker (OBJ · GLB · STL; the mesh centred and scaled to unit bounds, normals computed when missing); (b) a **Lighting** section exposing what the engine hardcodes — key angle · elevation · intensity, fill, rim, ambient, and a `Light orbit` whole-turns-per-loop toggle so the light can be the thing that moves; (c) engine loops accept canvas + pixi stages (the routing above), build.js's "engine loops can't host filters" branch retired with it.
- **Storage — the user's call (2026-10-10):** meshes live in R2, uploaded with the `bucket-r2` CLI (the ruled write path; the app stays read-only), and are picked from the media library — `MediaPickerDialog` with an `accept` for `.obj/.glb/.stl`, exactly as distress picks `.svg` (`LabsSourcePicker.jsx:84`). `meshSrc` is the proxied `/media/` URL, so the saved file references the bucket and survives reload, sync and other devices. No data URL, no IndexedDB, and item 13's asset store is not needed for meshes. A local upload button can wait.
